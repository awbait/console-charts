# subnet

Чарт создаёт одну подсеть kube-ovn для подов. Вы выбираете размер подсети, резерв адресов и разрешённые сети, а платформа бронирует диапазон в Netbox.

## Что создаёт чарт

| Секция | Что создаётся | Когда брать |
|---|---|---|
| `subnet` | Один ресурс `Subnet` | Нужна выделенная подсеть для существующих неймспейсов или для неймспейса, создаваемого чартом `namespace` |

При отдельном заказе неймспейсы указываются в `subnet.namespaces`. При подключении сабчартом к `namespace` привязку задаёт `namespaceBinding`.

Ресурс создаётся при `enabled: true`. Чарт не создаёт неймспейсы и квоты.

## Куда ставится релиз

`Subnet` создаётся на уровне кластера. Неймспейс установки релиза не определяет, какие неймспейсы используют подсеть.

При отдельном заказе укажите полные имена существующих неймспейсов в `subnet.namespaces`, например `nbox-dev-ns-app`. Пустой список оставляет подсеть без явных привязок.

При подключении к чарту `namespace` включается `namespaceBinding.enabled`. Имя неймспейса собирается из общих тегов и `global.namespacePurpose` либо берётся целиком из `global.namespaceOverride`. Поля `namespaceBinding.purpose` и `namespaceBinding.namespaceOverride` позволяют переопределить эти значения.

При автоматической привязке список `subnet.namespaces` должен быть пустым. Теги подсети и неймспейса задавайте вместе в `global.identity`.

## Теги окружения и проекта

Теги определяют окружение и проект подсети. В Console и ЛК их подставляет платформа. При установке через values заполните `identity`.

Если родительский чарт передал непустой `global.identity`, используется весь этот блок вместо локального `identity`.

| Поле | Нужно указать | Что это |
|---|---|---|
| `identity.instance` | При заполнении values | Тег инстанса из таблицы окружений |
| `identity.cluster` | При заполнении values | Тег кластера из таблицы окружений. Входит в имя подсети |
| `identity.project` | При заполнении values | Код проекта, от 2 до 9 символов. Входит в имя подсети |
| `global.identity` | При подключении к `namespace` | Общие `instance`, `cluster` и `project` для неймспейса, подсети и вейпоинта |

Код проекта содержит строчные латинские буквы, цифры и дефис. Дефис не может быть первым или последним символом.

| Окружение | `identity.cluster` | `identity.instance` |
|---|---|---|
| Infra-dev-ecpk | `inf` | `in` |
| dev-ecpk | `dev` | `id` |
| techsec-dev | `tco` | `ed` |
| dev-common | `dev` | `ed` |
| test-common | `tst` | `ed` |
| global | `gl` | `pr` |
| observability | `obs` | `pr` |
| techsec | `tcc` | `pr` |
| int-common | `cmi` | `pr` |
| ML | `ml` | `pr` |
| ext-common | `cme` | `pr` |

Выбирайте оба тега из одной строки. Схема проверяет допустимые значения полей `identity` по отдельности, но не их сочетание.

## Имена ресурсов

Имя подсети собирается по схеме `{identity.project}-{identity.cluster}-subnet-{назначение}`.

Например, проект `nbox`, кластер `dev` и назначение `app` дают имя `nbox-dev-subnet-app`.

Назначение задаётся в `subnet.name`. Оно содержит от 2 до 12 символов: строчные латинские буквы, цифры и дефис. Первый и последний символы должны быть буквой или цифрой.

При автоматической привязке пустое `subnet.name` наследует назначение из `namespaceBinding.purpose` или `global.namespacePurpose`. Полное имя неймспейса не заменяет назначение подсети.

Этот чарт использует схему имён, принятую в `namespace`. Стандартная для других чартов схема из пяти частей здесь не применяется. Тег `instance` входит в метки, но не в имя.

Имя подсети совпадает с именем, которое раньше создавал чарт `namespace`. При переходе сохраняйте теги и назначение, чтобы существующая подсеть не пересоздавалась. Имя длиннее 63 символов останавливает рендер.

## Метки на ресурсах

| Метка | Значение |
|---|---|
| `app` | `subnet` |
| `app.cpaas.io/name` | Имя релиза |
| `app.kubernetes.io/managed-by` | `Helm` |
| `helm.sh/chart` | Имя и версия чарта |
| `ecpk/instance` | Тег `instance` |
| `ecpk/cluster` | Тег `cluster` |
| `ecpk/project` | Тег `project` |

Теги берутся из `global.identity`, если он задан, иначе из `identity`. Метки `ecpk/*` помогают найти ресурсы окружения и проекта.

Аннотация `argocd.argoproj.io/sync-wave` имеет значение `-2`. Она задаёт порядок создания подсети в Argo CD.

| Поле | Нужно указать | Что это |
|---|---|---|
| `generic.labels` | Нет | Дополнительные метки подсети |
| `generic.annotations` | Нет | Дополнительные аннотации подсети |

При подключении к `namespace` эти поля находятся в `subnet.generic`. Метки и аннотации из `generic` родительского чарта на подсеть не передаются.

## Параметры заказа

В форме отдельного заказа доступны назначение, маска, число резервируемых адресов, разрешённые подсети и неймспейсы.

| Поле | Нужно указать | Что это |
|---|---|---|
| `subnet.name` | Да при отдельном заказе | Назначение подсети, от 2 до 12 символов |
| `subnet.mask` | Нет, значения по умолчанию нет | Поле для будущего бронирования диапазона в Netbox. В форме скрыто. Допустимые значения: `29`, `28`, `27`, `26`, `25` или `24`. Если задано, должно совпадать с маской в `subnet.cidrBlock` |
| `subnet.reservedIps` | Нет, по умолчанию `0` | Число адресов сразу за шлюзом, которые не будут выдаваться подам. От `0` до `16` |
| `subnet.allowSubnets` | Если нужен обмен с другими сетями | Дополнительные разрешённые диапазоны IPv4 с масками от `/0` до `/32` |
| `subnet.namespaces` | Для привязки к существующим неймспейсам | Список полных имён неймспейсов. При автоматической привязке оставьте пустым |

Укажите диапазон подсети вместе с маской в `subnet.cidrBlock`, например `10.24.8.0/26`. Адрес должен быть началом сети. Размер подсети определяется маской диапазона. Поле `subnet.mask` скрыто в форме и оставлено для будущего бронирования диапазона в Netbox. Оно необязательно и не имеет значения по умолчанию. Если вы задали `subnet.mask` в values, его значение должно совпадать с маской диапазона. Иначе рендер остановится. Если `subnet.mask` не задано, проверка совпадения масок не выполняется.

Шлюзом становится первый адрес после адреса сети. Он всегда исключён из выдачи подам и не входит в число `reservedIps`. Например, для `10.24.8.0/26` шлюзом будет `10.24.8.1`. При `reservedIps: 2` дополнительно резервируются `10.24.8.2` и `10.24.8.3`.

Резерв уменьшает число адресов для подов. После него должен оставаться хотя бы один адрес. Например, для `/29` допустим резерв не больше четырёх адресов.

Диапазоны `172.30.0.0/15`, `100.96.0.0/16` и `169.254.7.127/32` всегда добавляются к разрешённым. `100.96.0.0/16` - join-подсеть kube-ovn-cni, через которую проходят проверки kubelet. `169.254.7.127/32` - link-local адрес этих проверок при включённой ambient-сетке. Повторять системные диапазоны в `allowSubnets` не нужно.

После заказа параметры доступны через действие «Настроить подсеть» в карточке заказа. Назначение и маску в этой форме изменить нельзя.

## Параметры только в values

Эти поля скрыты в форме заказа.

| Поле | Нужно указать | Что это |
|---|---|---|
| `enabled` | Для создания подсети | При `true` создаётся `Subnet`. По умолчанию `false`, при заказе форма включает чарт |
| `subnet.cidrBlock` | Да при включённой подсети | Диапазон IPv4, который вы указываете в форме или values в формате `адрес/маска`, например `10.24.8.0/26`. Адрес должен быть началом сети. Маска определяет размер подсети |
| `subnet.natOutgoing` | Нет, по умолчанию `false` | NAT исходящего трафика средствами kube-ovn |
| `subnet.private` | Нет, по умолчанию `true` | Изоляция подсети. При `true` сетевой обмен разрешён только с диапазонами из `allowSubnets`, включая автоматически добавленный диапазон |
| `subnet.excludeIPs` | Нет | Дополнительные адреса или диапазоны `start..end`, которые нельзя выдавать подам. Все адреса должны находиться внутри `cidrBlock` |
| `subnet.gatewayType` | Нет, по умолчанию `distributed` | Тип шлюза: распределённый `distributed` или централизованный `centralized` |
| `subnet.gatewayNodes` | При `gatewayType: centralized` | Имена узлов шлюза через запятую, например `node-a,node-b` |

`excludeIPs` дополняет резерв шлюза и `reservedIps`. Указывать в нём автоматически резервируемые адреса не требуется.

Значения `subnet.default: false`, `subnet.protocol: IPv4` и `subnet.enableEcmp: false` зафиксированы схемой. Подсеть не становится подсетью по умолчанию, использует IPv4 и работает без ECMP.

## Подключение к чарту `namespace`

Поля этой секции нужны при подключении сабчартом. В отдельном заказе автоматическая привязка выключена.

| Поле | Нужно указать | Что это |
|---|---|---|
| `namespaceBinding.enabled` | `true` при подключении к `namespace` | Включает автоматическую привязку к неймспейсу родителя |
| `namespaceBinding.purpose` | Если назначение отличается от `global.namespacePurpose` | Назначение неймспейса. Также используется для подсети, если `subnet.name` пустое |
| `namespaceBinding.namespaceOverride` | Если полное имя не задано в `global.namespaceOverride` | Полное имя неймспейса вместо имени, собранного из тегов и назначения |
| `global.namespacePurpose` | Если назначение не переопределено | Общее назначение неймспейса |
| `global.namespaceOverride` | Нет | Общее полное имя неймспейса |

В values чарта `namespace` секция `namespaceBinding` находится по пути `subnet.namespaceBinding`, а параметры самой подсети по пути `subnet.subnet`.

## Когда рендер останавливается

При `enabled: false` все поля необязательны: секции `identity`, `subnet` и `namespaceBinding` можно не передавать или оставить незаполненными. При `enabled: true` схема требует `identity` с полями `instance`, `cluster`, `project` и секцию `subnet` с полями `name`, `cidrBlock`. Если передана секция `namespaceBinding`, в ней по-прежнему нужны `enabled`, `purpose` и `namespaceOverride`. Если корневой `enabled` отсутствует в проверяемых значениях, обязательность сохраняется.

Обязательность выше относится к значениям, непосредственно переданным валидатору JSON Schema. Например, без подмешивания `values.yaml` объект `{"enabled": false}` проходит проверку, а `{"enabled": true}` без `identity` и `subnet` отклоняется. Это позволяет проверять неполное описание выключенной подсети отдельно от Helm.

Helm перед проверкой схемы подмешивает `values.yaml`. Поэтому включённая подсеть без `identity` во входном файле использует дефолтные теги `id` / `dev` / `demo` и может успешно отрендериться. Условный `required` не запрещает такое наследование дефолтов и не требует явно передавать все поля в пользовательском файле.

Остальные параметры подсети используют значения по умолчанию из `values.yaml`, также указанные в схеме. Исключение: `mask` не имеет значения по умолчанию. Типы, форматы и неизвестные ключи проверяются и у выключенного чарта.

Проверки значений не дают создать подсеть с неверным диапазоном или привязкой:

- Подсеть включена, но `subnet.cidrBlock` пуст.
- `cidrBlock` записан не в формате `адрес/маска`, содержит неверный IPv4-адрес или маску вне диапазона от `/16` до `/30`.
- Адрес в `cidrBlock` не совпадает с первым адресом сети.
- Маска в `cidrBlock` не совпадает с заказанной в `subnet.mask`.
- `subnet.mask` не входит в список `29`, `28`, `27`, `26`, `25`, `24`.
- `subnet.reservedIps` не является целым числом от `0` до `16`.
- После адреса сети, шлюза, широковещательного адреса и резерва `reservedIps` не остаётся хотя бы одного адреса для подов.
- `subnet.excludeIPs` содержит неверный IPv4-адрес или диапазон не в формате `start..end`. Начало диапазона больше конца либо адреса находятся вне `cidrBlock`.
- `subnet.allowSubnets` содержит неверный IPv4 CIDR или маску вне диапазона от `/0` до `/32`.
- `subnet.gatewayType` отличается от `distributed` и `centralized`.
- Выбран `centralized`, но `subnet.gatewayNodes` пуст.
- В `subnet.namespaces` или в полном имени для автоматической привязки указано недопустимое имя. Разрешены строчные латинские буквы, цифры и дефис. Имя должно начинаться и заканчиваться буквой или цифрой и содержать не больше 63 символов.
- Включён `namespaceBinding.enabled`, но список `subnet.namespaces` не пуст.
- Не задано назначение подсети и его нельзя получить из настроек привязки.
- Для сборки имени неймспейса не задано назначение. Это требуется, если автоматическая привязка включена, а полное имя неймспейса не указано.
- Используемое назначение содержит меньше 2 или больше 12 символов либо недопустимые символы.
- Не заданы проект или кластер для сборки имени. Код проекта должен содержать от 2 до 9 символов. Для проекта и кластера допустимы строчные латинские буквы, цифры и дефис без дефиса по краям.
- Собранное имя ресурса длиннее 63 символов.
- При сборке имени отсутствует служебный код типа ресурса или используется код, отличный от `ns` и `subnet`.
- Задан устаревший выключатель `global.enable: false`. Для отключения используйте корневой `enabled: false`.

Схема также отклоняет неизвестные поля в описанных секциях, неверные типы значений, повторы в списках и недопустимые значения `identity`. Поля `subnet.default`, `subnet.protocol` и `subnet.enableEcmp` должны сохранять фиксированные значения.

При подключении к `namespace` родитель дополнительно проверяет совпадение тегов и имени неймспейса. Подсеть нельзя включить при выключенном родительском чарте или отключённой автоматической привязке.

## Файлы чарта

| Файл | Для чего |
|---|---|
| `values.yaml` | Значения по умолчанию. Подсеть выключена, ресурсы не создаются |
| `values.minimal.yaml` | Короткий пример одной подсети с привязкой к неймспейсу. Перед использованием нужны существующий неймспейс и забронированный диапазон |
| `values.full.yaml` | Полный справочник параметров с пояснениями |
| `values.schema.json` | Проверка значений и описание полей формы заказа |
| `view.schema.json` | Исходное описание формы заказа и действия «Настроить подсеть» для портала |
