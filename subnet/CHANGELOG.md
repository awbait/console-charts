# Changelog

Все заметные изменения чарта `subnet`
фиксируются в этом файле.

## Правила версионирования

- **MAJOR** - несовместимые изменения, требующие правок в твоём `values.yaml`.
- **MINOR** - новые возможности без поломки существующих.
- **PATCH** - исправления и улучшения, прозрачные для пользователя.

## Категории изменений

- **Added** - что появилось нового.
- **Changed** - что изменилось в поведении.
- **Deprecated** - что будет удалено в будущем.
- **Removed** - что удалено.
- **Fixed** - что исправлено.
- **Security** - изменения, влияющие на безопасность.

## [1.0.2] - 2026-10-15

### Fixed

- В форме заказа подсети диапазон теперь указывают вместе с маской в `subnet.cidrBlock`. Отдельное поле `subnet.mask` скрыто и больше не обязательно. Убрано значение по умолчанию `26`, из-за которого диапазон с другой маской не проходил проверку. Если `subnet.mask` задано в values, несовпадение с маской диапазона по-прежнему останавливает рендер. Если поле не задано, проверка совпадения масок не выполняется.

### Changed

- Обновлено описание переключателя «NAT исходящего трафика» в форме заказа подсети. При включённом NAT трафик пода за пределы кластера уходит с адресом узла. Выключайте NAT, если нужно сохранить адрес пода из подсети. Значение по умолчанию в чарте осталось `false`.

Правки в существующих `values.yaml` не нужны.

## [1.0.1] - 2026-10-15

### Fixed

- В форме заказа подсети поля `subnet.allowSubnets` и `subnet.namespaces` теперь можно не заполнять. Пустые списки по-прежнему означают отсутствие дополнительных разрешённых диапазонов и явной привязки к неймспейсам. Диапазон `172.30.0.0/15` добавляется к разрешённым всегда.
- При `namespaceBinding.enabled: true` заполненный список `subnet.namespaces` теперь отклоняется при проверке значений до установки. При автоматической привязке этот список оставляют пустым.

Правки в существующих `values.yaml` не нужны.

## [1.0.0] - 2026-10-13

### Added

- Первый выпуск чарта. Один заказ создаёт одну подсеть kube-ovn `Subnet`.
- Подсеть можно заказать отдельно и привязать к существующим неймспейсам через `subnet.namespaces`. При подключении сабчартом к `namespace` привязка задаётся через `namespaceBinding`.
- Размер подсети выбирается в `subnet.mask`. Платформа бронирует диапазон в Netbox и заполняет скрытое поле `subnet.cidrBlock`. Несовпадение масок останавливает рендер.
- Поле `subnet.reservedIps` резервирует от `0` до `16` адресов сразу за шлюзом. Адрес шлюза исключается из выдачи подам всегда. Дополнительные исключения можно задать в `subnet.excludeIPs`.
- Поле `subnet.allowSubnets` задаёт разрешённые сети. Диапазон `172.30.0.0/15` добавляется автоматически.
- Через values доступны настройки изоляции, NAT и типа шлюза. Для `subnet.gatewayType: centralized` обязательно указать `subnet.gatewayNodes`.
- Имя подсети сохраняет формат `{identity.project}-{identity.cluster}-subnet-{назначение}`, принятый в `namespace`.
- Теги окружения и проекта добавляются в метки `ecpk/*`. Общие теги родителя можно передать через `global.identity`, дополнительные метки и аннотации через `generic`.
- В карточке заказа доступно действие «Настроить подсеть». Назначение и маска в этой форме доступны только для чтения.
