# Тексты для пользователя пишет codex

Любой текст, который увидит пользователь портала Console, генерирует не Claude,
а codex (OpenAI Codex CLI, стоит на машине: `codex --version`). Claude собирает
факты, формулирует задание, принимает результат и кладёт его на место. Сам
текст Claude не сочиняет и не переписывает.

## Что считается текстом для пользователя

- Подписи в `values.schema.json`: `title`, `description`, `enumNames`. Портал
  строит по ним форму заказа.
- `templates/NOTES.txt`: сводка после установки.
- `README.md` чарта: портал показывает его в карточке сервиса.
- `CHANGELOG.md` чарта: портал показывает записи версии в каталоге.

## Что Claude пишет сам

Комментарии в `templates/`, сообщения коммитов, тела PR и issue, комментарии к
ним, `AGENTS.md`, `CONVENTIONS.md`, `CONTRIBUTING.md`, правила и скиллы,
комментарии в `values*.yaml` (их читает автор заказа как справочник по
параметрам, но это документация для разработчика, а не текст в интерфейсе).

## Порядок

**1. Бриф.** Файл в scratchpad сессии, не в репозитории. В нём:

- что за продукт и кто читатель: пользователь портала заказывает сервис через
  форму, он не разработчик чарта;
- факты: какой чарт и версия, что изменилось, где пользователь это видит, что
  ему нужно сделать;
- какие файлы с правилами текста codex должен прочитать до ответа:
  `CONVENTIONS.md` (разделы «README.md», «CHANGELOG.md», «NOTES.txt»,
  «values.schema.json»), для записи журнала ещё
  `.agents/skills/changelog/SKILL.md`, для подписей полей - схема соседнего
  эталонного чарта, чтобы словарь совпадал;
- запреты этого репозитория, явно: без длинного тире, без точек с запятой,
  без имён хелперов, шаблонов и внутренних сущностей, без команд в
  `NOTES.txt`;
- языки и формат ответа: «только содержимое, без пояснений и без обрамления
  в ```». Для нескольких подписей одной правки: один бриф со списком путей
  схемы, ответ списком «путь: текст» или готовым JSON-фрагментом.

Готовый ответ codex должен ложиться в файл без правок, поэтому формат
задаётся в брифе, а не чинится после.

**2. Запуск.** Без интерактива, только чтение, без сохранения сессии:

```bash
codex exec -s read-only --ephemeral -C <repo root> --color never -o <scratch>/out.md - < <scratch>/brief.md
```

Ответ приходит в `out.md`, ход работы в stdout (его можно отправить в лог
и не читать). Обычный прогон занимает до минуты, таймаут команде давать
5 минут.

**3. Приёмка.** Claude читает `out.md` и проверяет формально: нужный язык,
категория записи верная, нет длинного тире, нет «;», нет имён из шаблонов,
факты не искажены, схема после вставки остаётся валидным JSON. Подходит -
кладёт как есть. Не подходит - отправляет обратно новым запуском: тот же бриф
плюс «предыдущий вариант: ...» и «что не так: ...» по пунктам. Своими словами
Claude не исправляет. Механику править можно: отступы, кавычки JSON, переносы
строк.

**4. Codex недоступен** (команды нет, ошибка входа, нет сети): сказать об
этом пользователю и остановиться на этом тексте. Не писать его самому молча.
Если пользователь скажет писать самому, текст пометить в PR как написанный
без codex.

## Почему

Тексты для пользователя - продуктовая работа, и у неё один автор: так тон,
формулировки и словарь одинаковы во всём продукте, в портале и в чартах, а не
зависят от того, какая сессия правила файл. Claude в этой цепочке отвечает за
факты и за проверку, codex - за слова.
