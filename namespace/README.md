# namespace

Неймспейс - изолированное рабочее пространство вашей команды в кластере.
После заказа вы получите управляемый платформой `Namespace`, квоты ресурсов
и, при необходимости, выделенную сеть.

## Что создаётся

| Что создаётся | Когда |
|---|---|
| `Namespace` | Всегда, когда чарт включён |
| `ResourceQuota` | Всегда, когда чарт включён: лимиты CPU, памяти, числа подов и хранилищ |
| `Subnet` | Когда включена выделенная подсеть |

Ресурсы создаются только при включённом чарте. Служебный флаг включения
проставляет портал при заказе.

## Имена ресурсов

Имена ресурсов собираются автоматически по схеме:

```
{identity.project}-{identity.cluster}-{ns|subnet}-{назначение}
```

Укажите поле «Назначение неймспейса» (`global.namespacePurpose`). Остальные
части имени берутся из общих `global.identity` (при отсутствии - из локальных
`identity`). При включённой подсети используйте `global.identity`.
Например, получатся `nbox-dev-ns-app` и `nbox-dev-subnet-app`.

Тег проекта портал подставляет по команде, от имени которой сделан заказ.
В форме заказа заполнять его не нужно. Вручную его указывают только при
прямой установке чарта.

Назначение в `global.namespacePurpose` задаётся один раз для всего заказа.
Его используют и неймспейс, и подключённый вейпоинт, поэтому прокси
размещается в нужном неймспейсе.

| Поле | Что задаёт |
|---|---|
| `global.namespacePurpose` | Назначение для всего релиза, включая подключённые чарты |
| `namespace.name` | Назначение неймспейса. Переопределяет назначение только для самого неймспейса |
| `subnet.subnet.name` | Назначение подсети. Если поле пустое, берётся назначение неймспейса |

Значение `namespace.name` не применяется к подключённым чартам. Если вы
заполнили это поле и включили вейпоинт, повторите назначение в
`waypoint.namespacePurpose`. Иначе рендер остановится с просьбой указать
назначение в `global.namespacePurpose` или `waypoint.namespacePurpose`.

Назначение должно содержать от 2 до 12 символов: строчные латинские буквы,
цифры и дефис. Имя namespace обрезается до 63 символов; сабчарт Subnet
отклоняет имя длиннее 63 символов.

Если нужно задать имя неймспейса целиком, укажите `namespace.namespaceOverride`.
Имя не будет собираться из тегов и назначения. Например, значение `team-app`
создаст неймспейс `team-app`.

Поле `namespace.namespaceOverride` скрыто в форме портала. Оно предназначено
для прямой установки чарта или подключения его как сабчарта. Чтобы
подключённый вейпоинт использовал то же имя, укажите его также в
`global.namespaceOverride` или `waypoint.namespaceOverride`. Значение
`namespace.namespaceOverride` имеет приоритет над `global.namespaceOverride`.

Имя подсети по-прежнему собирается из тегов и назначения. Например,
`nbox-dev-subnet-app`. Переопределение имени неймспейса на неё не влияет.
Подсеть привязывается к неймспейсу с заданным именем. Метки `ecpk/*` и
`cpaas.io/*` не меняются.

Изменение имени у работающего релиза создаёт новый неймспейс. Argo CD удалит
старый неймспейс вместе со всем содержимым. Укажите полное имя при первом
заказе и не меняйте его у работающего релиза.

## Теги окружения и проекта

Блок «Окружение и проект» (`identity`) задаёт теги для всего релиза.
`project` и `cluster` образуют первые две части имени каждого ресурса.
Все три тега также добавляются на ресурсы как метки, по которым их можно
найти в кластере.

В форме заказа этот блок скрыт. Портал заполняет его по настройкам
`defaults` в `view.schema.json`.

Если неймспейс создаётся в составе другого чарта, общие теги можно задать
через `global.identity`. Они имеют приоритет над `identity` и применяются
также к вейпоинту. Например, `egress-gateway` использует эти общие теги
для двух неймспейсов, которые создаёт с помощью чарта `namespace`.

| Поле | Что это |
|---|---|
| `identity.instance` | Инстанс. Обязательный тег окружения, значение из таблицы ниже |
| `identity.cluster` | Кластер. Обязательный тег окружения, значение из таблицы ниже |
| `identity.project` | Проект. Обязательный тег, до 9 символов: строчные латинские буквы, цифры и дефис |

По умолчанию эти теги используются и в полях консоли платформы Alauda.
`identity.project` задаёт метку `cpaas.io/project` и аннотацию
`cpaas.io/project-inner-namespace`. `identity.cluster` задаёт метку
`cpaas.io/cluster`.

Если имена в Alauda отличаются от тегов окружения, их задают в полях
«Кластер в консоли платформы» (`namespace.cpaas.cluster`) и
«Проект в консоли платформы» (`namespace.cpaas.project`). Эти значения
заменяют теги только в cpaas-полях. Метки `ecpk/*` и имена ресурсов
остаются прежними.

При заказе через портал оба поля заполняются автоматически при сохранении:
кластер `global`, проект `dev`. Портал заменит введённые вами значения.
Вручную эти поля заполняют только при прямой установке чарта.

Теги инстанса и кластера для каждого окружения:

| Окружение | `identity.cluster` | `identity.instance` |
|---|---|---|
| Infra-dev-ecpk | `inf` | `in` |
| dev-ecpk | `dev` | `id` |
| techsec-dev | `tco` | `ed` |
| dev-common | `dev` | `ed` |
| test-common | `tst` | `ed` |
| global | `gl` | `pr` |
| observability | `obs` | `pr` |
| techsec | `tcc` | `pr` |
| int-common | `cmi` | `pr` |
| ML | `ml` | `pr` |
| ext-common | `cme` | `pr` |

При ручном заполнении выбирайте оба значения из одной строки таблицы.
Для каждого поля в схеме задан список допустимых значений. Проверка
выполняется отдельно для каждого поля, поэтому сочетание тегов из разных
окружений не вызовет ошибку.

## Метки на ресурсах

| Метка | Значение |
|---|---|
| `app` | `namespace` - имя чарта, не зависит от имени релиза |
| `app.cpaas.io/name` | Имя релиза |
| `app.kubernetes.io/managed-by` | `Helm` |
| `helm.sh/chart` | Имя и версия чарта |
| `ecpk/instance` | `identity.instance`, если тег задан |
| `ecpk/cluster` | `identity.cluster`, если тег задан |
| `ecpk/project` | `identity.project`, если тег задан |

У `Namespace` также есть метки `cpaas.io/cluster` и `cpaas.io/project`.
Их значения берутся из `namespace.cpaas`, а при пустых полях из `identity`.

Метка `namespace-role` задаётся полем «Роль неймспейса» (`namespace.role`).
Поле скрыто в форме заказа. Если значение не указано, используется `other`.

Поле «Уровень безопасности подов» (`namespace.podSecurity`) задаёт один уровень
для трёх меток Pod Security Standards: `enforce`, `audit` и `warn`.
Допустимые уровни: `restricted`, `baseline` и `privileged`.
Если поле пустое, метки определяет платформа.

Аннотация `argocd.argoproj.io/sync-wave` задаёт порядок создания ресурсов
в Argo CD. Для `Namespace` используется волна `-3`, для `ResourceQuota`
и `Subnet` волна `-2`. Поэтому неймспейс и подсеть создаются раньше
ресурсов, которые размещает внутри родительский чарт. Вне Argo CD
аннотация ни на что не влияет.

Свои метки и аннотации можно добавить через `generic.labels` и
`generic.annotations`. Они применяются ко всем ресурсам релиза.
Добавить их только на `Namespace`, без квот и подсетей, нельзя.

## Что нужно указать

| Поле | Нужно указать | Что это |
|---|---|---|
| `global.namespacePurpose` | да | Назначение. Последняя часть имени неймспейса, от 2 до 12 символов |
| `namespace.name` | нет | Назначение неймспейса. Переопределяет назначение только для самого неймспейса |
| `namespace.namespaceOverride` | нет | Полное имя неймспейса. Если указано, имеет приоритет над `global.namespaceOverride` |
| `global.namespaceOverride` | нет | Полное имя неймспейса, доступное подключённым чартам, включая вейпоинт |
| `namespace.displayName` | нет | Отображаемое имя неймспейса |
| `namespace.role` | нет | Роль неймспейса: `ingress`, `egress` или `other`. По умолчанию `other` |
| `namespace.podSecurity` | нет | Уровень Pod Security: `restricted`, `baseline` или `privileged` |
| `namespace.cpaas.cluster` | нет | Кластер в консоли платформы. Значение для `cpaas.io/cluster`. При пустом поле берётся `identity.cluster`, при заказе через портал ставится `global` |
| `namespace.cpaas.project` | нет | Проект в консоли платформы. Значение для `cpaas.io/project`. При пустом поле берётся `identity.project`, при заказе через портал ставится `dev` |
| `resourceQuotas.limits` | да | Лимиты CPU и памяти, например `cpu: "4"` и `memory: "8Gi"`. Без них рендер останавливается |
| `resourceQuotas.requests` | нет | Запросы CPU и памяти. По умолчанию берутся из лимитов |
| `resourceQuotas.storage` | нет | Квоты на хранилище. Объём по классам хранилища, см. ниже |
| `subnet` | нет | Подсети неймспейса. Для выделенной подсети нужен зарезервированный CIDR |

## Квоты на хранилище

В `resourceQuotas.storage` укажите общий объём хранилища для неймспейса по
каждому классу. Набор классов задаёт платформа. Добавить свой класс через
значения нельзя.

| Класс | Что это |
|---|---|
| `topolvm-mu` | Быстрый диск для частой записи. Выбирайте для очередей сообщений, журналов и аналитических баз |
| `topolvm-ri` | Экономичный диск для частого чтения. Выбирайте для кешей, поисковых индексов и данных, которые можно загрузить заново |
| `ceph-rbd` | Блочный том в сетевом хранилище Ceph. Выбирайте для баз данных и сервисов, которым нужен отдельный диск, сохраняющий данные при переезде пода на другой сервер |
| `ceph-rgw` | Класс объектного хранилища Ceph. Квота ограничивает объём, запрошенный томами этого класса |
| `cephfs-hot` | Общая файловая система CephFS на быстром пуле. Выбирайте для общих файлов нескольких реплик |

Для классов `topolvm-mu` и `topolvm-ri` данные хранятся на диске сервера без
копий. Для классов Ceph данные хранятся в сетевом хранилище. Один том
`cephfs-hot` могут одновременно подключить несколько подов.

Пустое значение означает, что неймспейсу не выдаются диски этого класса.
Задайте объём, например `50Gi` для `ceph-rbd`, `100Gi` для `ceph-rgw` или
`20Gi` для `cephfs-hot`.

```yaml
resourceQuotas:
  storage:
    topolvm-mu: "100Gi"
    topolvm-ri: "200Gi"
    ceph-rbd: "50Gi"
    ceph-rgw: "100Gi"
    cephfs-hot: "20Gi"
```

## Подсеть

Выделенную подсеть создаёт подключённый чарт `subnet` версии `1.0.0`. Один заказ неймспейса управляет одной подсетью.

В Console и ЛК укажите маску, число резервируемых адресов и разрешённые подсети. Платформа забронирует диапазон в Netbox, заполнит `subnet.subnet.cidrBlock` и включит `subnet.enabled`.

| Поле | Нужно указать | Что это |
|---|---|---|
| `subnet.subnet.mask` | Нет, по умолчанию `26` | Маска подсети: `29`, `28`, `27`, `26`, `25` или `24` |
| `subnet.subnet.reservedIps` | Нет, по умолчанию `0` | Число адресов сразу за шлюзом, которые не будут выдаваться подам. От `0` до `16` |
| `subnet.subnet.allowSubnets` | Если нужен обмен с другими сетями | Дополнительные разрешённые диапазоны IPv4 |
| `subnet.subnet.cidrBlock` | Заполняет платформа | Забронированный диапазон с маской, совпадающей с `subnet.subnet.mask`. В форме скрыт |
| `subnet.enabled` | Включает платформа | Создание подсети после бронирования диапазона. В форме скрыт |

Общие теги передавайте через `global.identity`. Их используют неймспейс, подсеть и вейпоинт.

Пример values после бронирования диапазона. Замените адресный диапазон и разрешённую сеть на значения вашего заказа.

```yaml
enabled: true

global:
  identity:
    instance: ed
    cluster: dev
    project: nbox
  namespacePurpose: app

subnet:
  enabled: true
  namespaceBinding:
    enabled: true
  subnet:
    name: ""
    mask: 26
    reservedIps: 2
    cidrBlock: "10.24.8.0/26"
    allowSubnets:
      - "10.25.0.0/16"
```

В этом примере создаётся подсеть `nbox-dev-subnet-app`, привязанная к неймспейсу `nbox-dev-ns-app`. Шлюз `10.24.8.1` исключается из выдачи подам всегда. Поле `reservedIps: 2` дополнительно резервирует адреса `10.24.8.2` и `10.24.8.3`.

После резервирования должен оставаться хотя бы один адрес для подов. Диапазон `172.30.0.0/15` всегда добавляется к разрешённым сетям.

Пустое `subnet.subnet.name` наследует назначение из `subnet.namespaceBinding.purpose` или `global.namespacePurpose`. Для существующей подсети сохраните прежнее назначение и теги, чтобы её имя не изменилось.

Оставьте `subnet.namespaceBinding.enabled: true`, а список `subnet.subnet.namespaces` пустым. Подсеть привяжется к неймспейсу автоматически.

Если вы задали `namespace.name`, повторите назначение в `subnet.namespaceBinding.purpose`. Если вы задали `namespace.namespaceOverride`, укажите то же полное имя в `global.namespaceOverride` или `subnet.namespaceBinding.namespaceOverride`. Несовпадение привязки останавливает рендер.

Дополнительные сетевые параметры скрыты в форме и задаются через values.

| Поле | Нужно указать | Что это |
|---|---|---|
| `subnet.subnet.private` | Нет, по умолчанию `true` | Изоляция подсети. Разрешает обмен только с разрешёнными диапазонами |
| `subnet.subnet.natOutgoing` | Нет, по умолчанию `false` | NAT исходящего трафика средствами kube-ovn |
| `subnet.subnet.excludeIPs` | Нет | Дополнительные исключённые адреса или диапазоны `start..end` внутри `cidrBlock` |
| `subnet.subnet.gatewayType` | Нет, по умолчанию `distributed` | Тип шлюза: `distributed` или `centralized` |
| `subnet.subnet.gatewayNodes` | При `gatewayType: centralized` | Имена узлов шлюза через запятую |
| `subnet.generic.labels` | Нет | Дополнительные метки подсети |
| `subnet.generic.annotations` | Нет | Дополнительные аннотации подсети |

Поля `generic.labels` и `generic.annotations` неймспейса на подсеть не действуют.

При отключении родительского чарта через `enabled: false` выключите также `subnet.enabled` и `serviceMesh.waypoint`.

## Переход с namespace 6.x

**BREAKING:** версия `7.0.0` создаёт подсеть через подключённый чарт `subnet` версии `1.0.0`. Перед обновлением измените values.

| Раньше | Теперь |
|---|---|
| `subnet.enable` | `subnet.enabled` |
| `subnet.subnets[0]` | `subnet.subnet` |
| `subnet.subnets[0].name` | `subnet.subnet.name` |
| `subnet.subnets[0].mask` | `subnet.subnet.mask` |
| `subnet.subnets[0].reservedIps` | `subnet.subnet.reservedIps` |
| `subnet.subnets[0].allowSubnets` | `subnet.subnet.allowSubnets` |
| `subnet.subnets[0].private` | `subnet.subnet.private` |
| `subnet.subnets[0].natOutgoing` | `subnet.subnet.natOutgoing` |
| `subnet.subnets[0].cidrBlock` | `subnet.subnet.cidrBlock` |
| `identity` | `global.identity` для общих тегов неймспейса, подсети и вейпоинта |
| `generic.labels` для подсети | `subnet.generic.labels` |
| `generic.annotations` для подсети | `subnet.generic.annotations` |

Перенесите параметры подсети без изменения их смысла. `mask` по-прежнему задаёт размер бронируемого диапазона, а `reservedIps` задаёт число адресов сразу за шлюзом. Заменять `reservedIps` списком `excludeIPs` не нужно. Маска в `cidrBlock` должна совпадать с `mask`.

Удалите старые ключи `subnet.enable` и `subnet.subnets` из values, в том числе если подсеть выключена. Они останавливают рендер с подсказкой по переходу.

Сохраните прежние теги, назначение и диапазон подсети. Формат имени не изменился: `nbox-dev-subnet-app` останется `nbox-dev-subnet-app`. Существующая подсеть при таком переходе не пересоздаётся.

Один заказ теперь управляет одной подсетью. Если в `subnet.subnets` было несколько элементов, до обновления перенесите управление дополнительными подсетями в отдельные заказы чарта `subnet`. Сохраните их имена и диапазоны. Без такого переноса обновление удалит дополнительные подсети.

Общие теги задавайте в `global.identity`. Несовпадение тегов неймспейса и подсети останавливает рендер. Метки и аннотации, нужные подсети, укажите в `subnet.generic`. Настройки `generic` неймспейса больше на неё не распространяются.

Оставьте `subnet.namespaceBinding.enabled: true` и пустой список `subnet.subnet.namespaces`. Если назначение задано в `namespace.name`, повторите его в `subnet.namespaceBinding.purpose`. Если полное имя задано в `namespace.namespaceOverride`, используйте то же значение в `global.namespaceOverride` или `subnet.namespaceBinding.namespaceOverride`.

## Сервисная сетка

Поле «Подключить сервисную сетку» (`serviceMesh.enabled`) позволяет включить или
выключить сетку только в кластере `dev`. В остальных кластерах она
включена платформой, и значение этого поля не влияет на результат.
Неймспейс получает метки Istio ambient и разрешение на сетевые политики.
Исключения задаются полями `serviceMesh.never` и `serviceMesh.discovery`,
описанными ниже.

Поле «Подключить прокси для правил доступа» (`serviceMesh.waypoint`) подключает
вейпоинт: прокси для обмена внутри неймспейса. Он нужен, когда правила
доступа проверяют не только адрес, но и сам запрос.
Без включённой сетки рендер останавливается.

По умолчанию вейпоинт размещается в неймспейсе, имя которого определяется
через `global.namespacePurpose`. Дополнительно указывать неймспейс
для прокси не нужно.

Поля `waypoint.namespaceOverride` и `waypoint.namespacePurpose` имеют
приоритет над значением из `global`. Если вы их заполняете, они должны
указывать на создаваемый неймспейс. При расхождении рендер останавливается.

Поле «Исключить из сервисной сетки» (`serviceMesh.never`) исключает неймспейс
из сетки в любом кластере, в том числе там, где она включена платформой.
На `Namespace` устанавливается метка `istio.io/dataplane-mode: none`.

Этот режим нужен транзитным шлюзам, работу которых нарушает перехват
трафика ambient. Например, `egress-gateway` использует его для неймспейса
с `VpcEgressGateway`. Совмещать этот режим с вейпоинтом нельзя.

Поле «Показывать сервисы без перехвата трафика» (`serviceMesh.discovery`)
делает сервисы неймспейса доступными из сетки. При этом поды остаются вне
ambient, и их трафик не перехватывается. На `Namespace` устанавливается только
метка `istio-discovery: enabled`, без `istio.io/dataplane-mode: ambient`.

Режим действует в любом кластере, в том числе там, где сетка включена
платформой. Поле `serviceMesh.never` имеет приоритет над этим режимом.
Совмещать `serviceMesh.discovery` с вейпоинтом нельзя.

## Когда рендер останавливается

- Теги `identity` не заданы или содержат недопустимые значения.
- Поле `serviceMesh.waypoint` включено, но сетка выключена либо включено
  `serviceMesh.never` или `serviceMesh.discovery`.
- Поле `serviceMesh.waypoint` включено, но вейпоинт настроен на другой
  неймспейс. Это происходит, если назначение задано в `namespace.name`
  и не повторено в `waypoint.namespacePurpose` либо поля `waypoint.*`
  указывают на другой неймспейс.
- Если `namespace.namespaceOverride` или `global.namespaceOverride` содержит
  недопустимое имя. Используйте строчные латинские буквы, цифры и дефис.
  Имя должно начинаться и заканчиваться буквой или цифрой и быть не длиннее
  63 символов.
- Если включён вейпоинт, а имя указано только в
  `namespace.namespaceOverride`. Укажите имя в `global.namespaceOverride` или
  повторите его в `waypoint.namespaceOverride`.
- Назначение неймспейса не задано, содержит меньше 2 или больше 12 символов
  либо не соответствует набору: строчные латинские буквы, цифры и дефис.
- В `namespace.podSecurity` указано непустое значение, отличное от
  `restricted`, `baseline` и `privileged`.
- Лимиты CPU или памяти не заданы в `resourceQuotas.limits`.
- В values остались старые ключи `subnet.enable` или `subnet.subnets`. Замените их на `subnet.enabled` и `subnet.subnet`, даже если подсеть выключена.
- Подсеть включена, но `subnet.subnet.cidrBlock` не задан.
- CIDR подсети содержит неверный IPv4-адрес, записан не в формате `адрес/маска`, имеет маску вне диапазона от `/16` до `/30` или начинается не с первого адреса сети.
- Маска в `subnet.subnet.cidrBlock` не совпадает с `subnet.subnet.mask`. Для `mask` допустимы только `29`, `28`, `27`, `26`, `25` и `24`.
- Значение `subnet.subnet.reservedIps` не является целым числом от `0` до `16` либо после резервирования не остаётся хотя бы одного адреса для подов.
- Поле `subnet.subnet.excludeIPs` содержит неверные адреса, диапазоны не в формате `start..end`, адреса вне CIDR или диапазоны в обратном порядке.
- Поле `subnet.subnet.allowSubnets` содержит неверный IPv4 CIDR или маску вне диапазона от `/0` до `/32`.
- Поле `subnet.subnet.gatewayType` отличается от `distributed` и `centralized` либо для `centralized` не задано `subnet.subnet.gatewayNodes`.
- Назначение подсети не задано и не наследуется, содержит меньше 2 или больше 12 символов либо недопустимые символы. Собранное имя подсети не должно быть длиннее 63 символов.
- Теги неймспейса и подсети не совпадают. Задайте общие теги в `global.identity`.
- При включённой подсети отключён `subnet.namespaceBinding.enabled` или заполнен список `subnet.subnet.namespaces`. Для подсети неймспейса нужна автоматическая привязка и пустой список.
- Полное имя в `subnet.namespaceBinding.namespaceOverride` недопустимо или подсеть привязывается к другому неймспейсу. Согласуйте назначение и полное имя с настройками создаваемого неймспейса.
- Подсеть включена при `enabled: false` у родителя. Выключите также `subnet.enabled`.

## Файлы чарта

| Файл | Для чего |
|---|---|
| `values.yaml` | Значения по умолчанию: минимум, при котором проходит рендер |
| `values.minimal.yaml` | Короткий рабочий пример: неймспейс и квоты, без подсети |
| `values.full.yaml` | Полный справочник: все параметры с пояснениями |
| `values.schema.json` | Схема значений: проверка при установке и форма заказа в портале |
