# namespace

Чарт создаёт изолированное рабочее пространство в кластере: управляемый
платформой `Namespace`, квоты ресурсов и, при необходимости, выделенную сеть.

## Что создаёт чарт

| Что создаётся   | Когда                                                        |
|-----------------|--------------------------------------------------------------|
| `Namespace`     | Всегда, когда чарт включён                                   |
| `ResourceQuota` | Всегда: лимиты CPU, памяти, числа подов и хранилищ           |
| `Subnet`        | Когда включена выделенная подсеть                            |

Ресурсы создаются, только когда чарт включён. Это служебный флаг, его проставляет
консоль при заказе.

## Имена ресурсов

Имя каждого ресурса чарт собирает сам:

```
{identity.project}-{identity.cluster}-{ns|subnet}-{назначение}
```

Заказ называет только назначение: `namespace.name` для неймспейса и
`subnet.subnets[].name` для подсети. Остальное берётся из `identity`, поэтому имя
ресурса и его теги не могут разойтись. Примеры: `nbox-dev-ns-app`,
`nbox-dev-subnet-app`.

Назначение - 2..12 символов, строчные латинские буквы, цифры и дефис. Готовое имя
обрезается до 63 символов.

## Теги окружения и проекта

Секция `identity` задаётся один раз на релиз. `project` и `cluster` дают первые
две части имени каждого ресурса, и все три тега проставляются на ресурсы чарта
как labels, по которым ресурсы находятся в кластере.

В форме заказа секция скрыта: значения проставляет портал (блок `defaults` в
`view.schema.json`).

| Поле                | Что это                                                                       |
|---------------------|--------------------------------------------------------------------------------|
| `identity.instance` | Тег инстанса окружения. Обязателен, значение из таблицы ниже                    |
| `identity.cluster`  | Тег кластера окружения. Обязателен, значение из таблицы ниже                    |
| `identity.project`  | Тег проекта. Обязателен, до 9 символов: строчные латинские буквы, цифры и дефис |

Эти же теги уходят в cpaas-поля неймспейса: `identity.project` - в label
`cpaas.io/project` и annotation `cpaas.io/project-inner-namespace`,
`identity.cluster` - в label `cpaas.io/cluster`. Отдельных `projectName` и
`clusterName` у чарта больше нет.

Пара тегов окружения:

| Окружение      | `identity.cluster` | `identity.instance` |
|----------------|--------------------|---------------------|
| Infra-dev-ecpk | `inf`              | `in`                |
| dev-ecpk       | `dev`              | `id`                |
| techsec-dev    | `tco`              | `ed`                |
| dev-common     | `dev`              | `ed`                |
| test-common    | `tst`              | `ed`                |
| global         | `gl`               | `pr`                |
| observability  | `obs`              | `pr`                |
| techsec        | `tcc`              | `pr`                |
| int-common     | `cmi`              | `pr`                |
| ML             | `ml`               | `pr`                |
| ext-common     | `cme`              | `pr`                |

Оба поля описаны в схеме значений перечислением. Берите значения строкой
таблицы: схема проверяет каждое поле по отдельности и не поймает пару из разных
окружений.

## Labels на ресурсах

| Label                          | Значение                                                  |
|--------------------------------|-----------------------------------------------------------|
| `app`                          | `namespace` - имя чарта, не зависит от имени релиза |
| `app.cpaas.io/name`            | Имя релиза                                                 |
| `app.kubernetes.io/managed-by` | `Helm`                                                     |
| `helm.sh/chart`                | Имя и версия чарта                                         |
| `ecpk/instance`                | `identity.instance`, если тег задан                        |
| `ecpk/cluster`                 | `identity.cluster`, если тег задан                         |
| `ecpk/project`                 | `identity.project`, если тег задан                         |

У `Namespace` вдобавок есть cpaas-labels `cpaas.io/cluster` и `cpaas.io/project`
из `identity` и `namespace-role` из `namespace.role`. Роль в форме заказа скрыта:
без явного значения ставится `other`.

Свои labels и annotations добавляются через `generic.labels` и
`generic.annotations`. Задаются только на весь релиз сразу, отдельно по ресурсам
их не задать. У `Namespace` есть свои `namespace.labels` и
`namespace.annotations` - они добавляются только к нему.

## Что нужно указать

| Поле                      | Нужно указать | Что это                                                        |
|---------------------------|---------------|-----------------------------------------------------------------|
| `namespace.name`          | да            | Назначение namespace, 2..12 символов: последняя часть имени      |
| `namespace.displayName`   | нет           | Отображаемое имя namespace                                      |
| `namespace.role`          | нет           | Роль namespace: `ingress`, `egress` или `other`, по умолчанию `other` |
| `resourceQuotas.limits`   | да            | Лимиты CPU и памяти, например `cpu: "4"` и `memory: "8Gi"`      |
| `resourceQuotas.requests` | нет           | Запросы CPU и памяти, по умолчанию берутся из лимитов           |
| `resourceQuotas.storage`  | нет           | Объём по классам хранилища, см. ниже                            |
| `subnet`                  | нет           | Выделенная подсеть, нужен зарезервированный CIDR                |

## Квоты на хранилище

`resourceQuotas.storage` - это объём на весь неймспейс по каждому классу
хранилища. Классы фиксированы платформой, свои в значениях не завести:

| Класс        | Что это                                                                     |
|--------------|------------------------------------------------------------------------------|
| `topolvm-mu` | Быстрый диск для частой записи. Берите его для очередей сообщений, журналов и аналитических баз |
| `topolvm-ri` | Экономичный диск для частого чтения. Берите его для кешей, поисковых индексов и данных, которые можно загрузить заново |

Пустое значение означает, что такой диск неймспейсу не выдаётся. Оба класса
держат данные на диске того сервера, где работает сервис, и копий на других
серверах не делают: восстановление после отказа - забота самого сервиса.

```yaml
resourceQuotas:
  storage:
    topolvm-mu: "100Gi"
    topolvm-ri: "200Gi"
```

## Подсеть

Подсеть стоит включать, только если CIDR заранее зарезервирован в Netbox. Адрес
шлюза вычисляется из CIDR автоматически и добавляется в исключения, подсеть
создаётся изолированной. Остальные параметры подсети зафиксированы платформой и
через значения не настраиваются.

## Service Mesh

Флаг `serviceMesh.enabled` включается на уровне окружения, а не пользователем.
Когда он включён, namespace получает метки Istio ambient и разрешение на сетевые
политики.

## Когда рендер останавливается

- не заданы теги `identity` или их значения вне допустимых;
- не задано назначение namespace, оно короче 2 или длиннее 12 символов либо
  записано не строчными латинскими буквами, цифрами и дефисом;
- подсеть включена, но у неё не задано назначение или CIDR;
- CIDR подсети записан не в формате «адрес/маска» либо маска меньше 24;
- последний октет адреса в CIDR больше 254, из-за чего нельзя вычислить шлюз.

## Файлы чарта

| Файл                  | Для чего                                                       |
|-----------------------|-----------------------------------------------------------------|
| `values.yaml`         | Значения по умолчанию: минимум, при котором проходит рендер       |
| `values.minimal.yaml` | Короткий рабочий пример: namespace и квоты, без подсети          |
| `values.full.yaml`    | Полный справочник: все параметры с пояснениями                   |
| `values.schema.json`  | Схема значений: проверка при установке и форма заказа в портале  |
