# secret-store

Чарт открывает вашему пространству доступ к секретам StarVault. Сам он секретов
не хранит и не переносит: он создаёт два ресурса, по которым External Secrets
Operator знает, куда ходить и от чьего имени.

Дальше секреты забирают другие заказы. Например, `ingress-gateway` для точки
входа с `tlsMode: Terminate` создаёт `ExternalSecret`, тот читает сертификат
через этот `SecretStore` и кладёт его в обычный секрет кластера.

## Что создаёт чарт

| Что создаётся    | Когда                                             |
|------------------|---------------------------------------------------|
| `ServiceAccount` | Всегда, если `serviceAccount.create` не выключен  |
| `SecretStore`    | Всегда                                            |

Ресурсы создаются в namespace релиза. Namespace чарт не создаёт и не меняет:
заказ ставится в уже существующее пространство.

## Что нужно от вас

Роль в StarVault, которую вам выдали для этого пространства. Всё остальное -
адрес StarVault, движок KV, метод аутентификации - платформенные значения,
они приезжают вместе с чартом и в форме заказа не показываются.

## Теги окружения и проекта

Секция `identity` задаётся один раз на релиз. В имена ресурсов эти теги не
входят, но проставляются на них как labels, по которым ресурсы находятся в
кластере.

| Поле                | Что это                                                                       |
|---------------------|--------------------------------------------------------------------------------|
| `identity.instance` | Тег инстанса окружения. Обязателен, значение из таблицы ниже                    |
| `identity.cluster`  | Тег кластера окружения. Обязателен, значение из таблицы ниже                    |
| `identity.project`  | Тег проекта. Обязателен, до 9 символов: строчные латинские буквы, цифры и дефис |

Пара тегов окружения:

| Окружение      | `identity.cluster` | `identity.instance` |
|----------------|--------------------|---------------------|
| Infra-dev-ecpk | `inf`              | `in`                |
| dev-ecpk       | `dev`              | `id`                |
| techsec-dev    | `tco`              | `ed`                |
| dev-common     | `dev`              | `ed`                |
| test-common    | `tst`              | `ed`                |
| global         | `gl`               | `pr`                |
| observability  | `obs`              | `pr`                |
| techsec        | `tcc`              | `pr`                |
| int-common     | `cmi`              | `pr`                |
| ML             | `ml`               | `pr`                |
| ext-common     | `cme`              | `pr`                |

## Имена ресурсов

Оба ресурса носят имена из значений, а не пятичастное имя платформы
(`{instance}-{cluster}-{kindShort}-{project}-{name}`). Это сознательное
исключение, и вот почему:

- имя `SecretStore` пишут в других заказах (у сертификата в `ingress-gateway`
  это поле «Хранилище»), поэтому оно должно быть коротким и одинаковым везде;
- имя `ServiceAccount` собирается из имени хранилища
  (`external-secrets-<хранилище>`), чтобы два хранилища в одном пространстве не
  делили один аккаунт.

По умолчанию это `vault` и `external-secrets-vault`. Второе хранилище в том же
пространстве назовите иначе: имя занято на пару (namespace, тип ресурса), и
портал не даст завести одноимённое.

## Секция `store`

| Поле               | Нужно указать | Что это                                                              |
|--------------------|---------------|------------------------------------------------------------------------|
| `auth.role`        | да            | Роль в StarVault, обычно имя команды                                   |
| `auth.mountPath`   | нет           | Mount метода аутентификации без префикса `auth/`, по умолчанию `kubernetes` |
| `name`             | нет           | Имя хранилища, по умолчанию `vault`. Его выбирают в других заказах      |
| `server`           | нет           | Адрес StarVault, платформенное значение                                |
| `path`             | нет           | Движок KV, в котором лежат ваши секреты, по умолчанию `kv`             |
| `version`          | нет           | Версия движка KV, по умолчанию `v2`                                    |
| `caBundle`         | нет           | Сертификат УЦ StarVault в base64, если кластер ему не доверяет         |
| `caProvider`       | нет           | Ссылка на `ConfigMap` или `Secret` с этим сертификатом                 |
| `apiVersion`       | нет           | `apiVersion` ресурса `SecretStore` для старого оператора               |

Версия движка KV влияет на то, как пишутся пути в заказах, которые читают
секреты: для `v2` путь пишется без `data/`, оператор подставляет его сам.

## Что должно быть готово со стороны StarVault

Роль должна существовать, и её политика должна давать чтение по тем путям, за
которыми вы придёте. Роль нарезается на команду и обычно называется её именем.
Чарт этого не создаёт и создать не может: это делается на стороне StarVault.

Пока роль не готова, релиз выкатится, но `SecretStore` не станет валидным, и
секреты, которые от него зависят, останутся пустыми. У точки входа гейтвея это
выглядит так: listener поднялся, а сертификата нет.

## Когда рендер останавливается

- не заданы `identity.instance` или `identity.cluster` либо в них недопустимые
  символы;
- `identity.project` длиннее 9 символов или содержит недопустимые символы;
- не задана `store.auth.role`;
- не задан `store.server`;
- имя `SecretStore` или `ServiceAccount` длиннее 63 символов или не в
  DNS-формате.

## Файлы чарта

| Файл                  | Для чего                                                       |
|-----------------------|------------------------------------------------------------------|
| `values.yaml`         | Значения по умолчанию: всё, кроме роли                           |
| `values.minimal.yaml` | Короткий рабочий пример: теги и роль                             |
| `values.full.yaml`    | Полный справочник: все параметры с пояснениями                   |
| `values.schema.json`  | Схема значений: проверка при установке и форма заказа в портале  |
